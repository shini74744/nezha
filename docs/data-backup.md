# 数据备份

入口：后台 → 设置 → 数据备份，仅管理员可用。备份覆盖面板配置、SQLite 数据库及其中的历史数据、历史监控存储、上传文件和数据目录中的密钥文件。不会升级服务器 Agent，也不会启用 SSH 监测或修改业务网络。

## 备份目标

可以选择多台机器，同一轮使用同一份数据快照，逐台传输并独立校验。一台失败不阻止其他目标完成。

- 从服务器列表选择：填写备份位置和端口，点击自动对接。现有 Agent 执行面板生成的专属安装命令，从本仓库下载 DDnezha 备份接收端；无需批量升级 Agent。
- 外部机器：选择手动添加，填写地址和目录，生成专属命令，在该机器执行后测试连接、保存。
- 已有 SFTP：也可以填写现有 SSH/SFTP 账号，使用密码或无密码私钥登录，并测试、确认服务器指纹。

接收端默认端口为 2022，默认位置为 /var/lib/ddnezha-backup/backups，可以在添加目标时修改。此端口独立于业务 SSH，不需要开放 SSH 22 端口。网络、防火墙和云安全组需要允许面板连接所选备份端口；安装脚本不会自动调整这些规则。

独立接收端仅用于备份：每个目标使用独立密钥，连接只允许访问对应备份目录；不接受 shell、命令执行、端口转发、符号链接或硬链接创建，不允许覆盖或删除以前已完成的备份。虚拟备份账号不是系统 SSH 登录账号。 接收端目录需要支持硬链接，以原子方式提交文件；并发提交同名文件只允许一个成功，不覆盖已有备份。

自动安装先支持 Linux amd64、arm64、armv7，使用 systemd 或 OpenRC；程序和安装脚本分别校验 SHA-256。Agent 离线、关闭远程命令、系统不支持、端口占用、下载失败或接收端无法连接都会显示错误。命令只包含公钥，面板私钥不会发送到目标机器。

每个目标须使用独立目录。安装遇到其他程序的同名安装位置、非空业务目录、目录重叠或身份密钥缺失时会停止，不覆盖原有业务文件。重复执行同一条安装命令保留接收端身份；已运行的同版本接收端动态读取新增授权，不需要重启。

Windows 面板的历史监控引擎存在在线快照清理限制，启用历史监控时暂不支持完整在线备份；操作会明确报错，不创建快照、不停止面板。此时请停机后备份完整数据目录。Linux 面板的在线完整备份不受此限制。

## 时间与进度

支持手动、按间隔、每日和数据变化后自动备份。实时模式按设置的最短间隔合并变化，并不是零延迟同步或热备切换。每轮均生成完整、可独立恢复的备份包；上一轮未完成时不会并发启动下一轮。

每轮显示开始、完成时间、备份目标和最终结果。目标分别显示准备快照、连接、打包传输、校验的阶段，处理进度、实际传输字节数和速度。源数据处理百分比与压缩后传输大小分别展示，不将估算大小伪装成精确传输总量。远端文件完整回读、SHA-256 相符后才标记成功。

失败原因保留在记录中。重试会创建新轮次，使用当时的新快照，仅发送到选择的未完成目标。面板重启时，未确认完成的任务标记中断。删除目标只移除面板连接设置，保留目标机器上的接收端和备份文件。

备份包当前不会自动清理旧轮次。请按实际容量设置频率并自行保留所需文件；空间不足时会失败并显示原因，不静默删除历史备份。面板准备快照时检查数据库副本与预留空间；运行中至少保留 512 MiB，独立接收端写入时至少保留 256 MiB。

## 数据保护

SQLite 使用在线备份接口并检查快照完整性；历史监控使用存储引擎快照，传输期间不停止数据采集。各类存储在准备阶段依次取快照，时间可能相差数秒，不宣称跨存储单一事务快照。普通文件先固定副本，多台目标收到同一代文件。

传输使用 SFTP，连接绑定服务器指纹。自动对接的指纹由原 Agent 的已认证连接返回，并在 SSH 认证时验证；手动连接通过测试记录首次确认的指纹，以后指纹变化会拒绝连接。

连接密码、私钥和备份加密密码在面板数据库中加密保存，接口不回显；加密凭证密钥位于数据目录的 backup-credentials.key，恢复时必须一并恢复。备份文件和接收端配置使用私有权限。完整备份包含面板敏感配置，建议开启备份包加密并另行保存恢复密码。

开启加密使用 age 密码加密，文件为 .tar.gz.age；关闭则为 .tar.gz。修改密码只影响以后生成的备份，旧备份仍需要当时的密码。

## 校验与恢复

1. 在可信机器上执行 sha256sum -c 对应的 .sha256 文件，确认备份包完整。
2. 加密包先解密：age --decrypt -o backup.tar.gz backup.tar.gz.age。按提示输入备份时的密码，不把密码写进命令历史。
3. 将压缩包解压到独立目录，检查 manifest.json 中每个文件的大小和 SHA-256；SQLite 可执行 PRAGMA integrity_check。
4. 正式替换前停止面板，保留现有数据副本。按原部署方式恢复 data 目录中的数据库、配置、密钥、上传文件和 tsdb 历史数据，恢复适当的目录属主。
5. 如原来使用自定义配置、数据库或 TSDB 路径，将包内 data/config.yaml、data/sqlite.db、data/tsdb 放回对应路径。先在隔离环境验证登录、服务器配置及历史曲线，再正式启动。

安装文件位于 backup/scripts/install.sh；独立接收端源码位于 cmd/backup-receiver 和 pkg/backupreceiver。发布版本使用 backup-v0.1.2 标签及同名 Release，包含各架构二进制和 SHA256SUMS。面板生成的命令绑定该版本与安装脚本校验值，避免运行漂移的安装脚本。

## 接口权限

数据备份仅限管理员；服务器范围受限的 API 令牌不能导出完整面板。自动安装还需要远程命令权限（nezha:server:exec），仅有管理员数据管理权限的令牌不能在目标服务器执行安装。
