# DDnezha Agent 生命周期隔离

Agent v1.0.2 与配套主面板 v0.0.4 引入独立生命周期。版本以正式 Releases 和各自版本入口为准；仓库文档不代表某台线上节点已完成迁移。只隔离安装、升级、卸载，不修改通信协议，不增加禁止官方／自有版本互连的限制。原有一机一密、先密钥后 UUID 验证和封禁规则保持。

## 独立命名

| 项目 | DDnezha |
| --- | --- |
| POSIX 程序与配置 | `/opt/DDnezha/DDnezha`、`/opt/DDnezha/config.yml` |
| Windows 程序与配置 | `C:\DDnezha\DDnezha.exe`、`C:\DDnezha\config.yml` |
| 默认服务 | `DDnezha`（systemd 为 `DDnezha.service`） |
| 多配置服务 | `DDnezha-配置路径哈希前七位` |
| 安装参数 | `DDNZ_SERVER`、`DDNZ_CLIENT_SECRET`、`DDNZ_TLS`、`DDNZ_UUID` |
| 下载资产 | `DDnezha_系统_架构.zip`，只从 `shini74744/nezha` |
| POSIX 安装脚本下载名 | `DDnezha.sh` |
| 归属标记 | 程序旁 `.DDnezha-owned`，内容为 `DDnezha` |

不读官方的 `NZ_*` 环境变量，不自动接管 `/opt/nezha/agent`、`C:\nezha`、官方服务或其他程序。YAML 配置字段不改名，避免丢失原有配置。安装器检查已有归属；程序、配置、目录不能通过链接指向其他安装。归属标记用于防止误操作，不是对抗 root／管理员的安全边界。

## 安装、升级、卸载

面板安装命令同时携带当前机器 UUID 和独立密钥。安装器在新目录独立安装，不复制官方配置，不停止官方服务。新系列后续更新验证独立通道 `DDnezha-agent-v1`、版本、平台、SHA-256 及 ZIP 内文件名，再替换自身程序。

在已下载的新版脚本目录执行：

```sh
./DDnezha.sh uninstall
# 未设置执行权限时：
sh DDnezha.sh uninstall
```

Windows 在管理员 PowerShell 中运行独立脚本：

```powershell
.\DDnezha.ps1 uninstall
```

脚本只卸载自有目录顶层配置对应的 DDnezha 服务，成功后才删除对应配置；保留程序、历史备份和面板数据。不需要联网、不解除 UUID／密钥封禁。配置含认证信息，请按需预先备份。不要向旧 `agent.sh` 传卸载参数试探：某些旧脚本会忽略参数并重新安装。

面板删除节点时仍先删除并封禁认证，再对原在线连接尝试一次 UUID 绑定清理。新清理脚本只识别 DDnezha 标准目录和归属标记，不碰旧目录／官方 Agent。非标准、未迁移或离线节点需另行核实，不会重连后自动卸载。

## 现有节点迁移

旧 v1.0.1 更新器只认旧通道和旧资产名，因此会拒绝新包，不会把 DDnezha 覆盖到旧共享路径。必须逐台迁移，不能仅点击旧升级按钮：

1. 确认实际程序、服务、配置、系统和架构，并将运行实例的 UUID、独立密钥、面板地址与本面板记录逐项匹配。多配置机器只迁移匹配的一个实例，不按目录批量接管；其他配置（包括未运行的配置）、服务和共享旧二进制都保留。备份目标配置、旧程序引用及服务定义，并记录其他实例的文件校验值与进程身份。无法确认归属时停止，不猜测。
2. 在新目录准备经过校验的 DDnezha 程序、归属标记和该节点配置；保留 UUID、独立密钥、TLS、代理、采集、禁用开关等全部字段。不要借用其他节点认证。
3. 只停止已确认归属本项目的旧实例，再启动新实例；避免同一 UUID 双进程同时上报。官方实例保持运行。
4. 核对新路径、新服务名、新版本、实时上报、能力及原节点 ID；失败时停止新实例并恢复旧实例，避免双连接。
5. 验证后保持目标旧服务禁用，保留旧配置、服务定义及程序供回滚；不递归删除共享目录、不覆盖共享二进制，不使用 `agent.sh uninstall` 或全实例卸载命令进行迁移。未确认的新连接会触发单实例回滚。离线或特殊系统单独处理。

`agent/scripts/migrate-instance-systemd.sh` 是受控迁移底层工具，不是自动识别归属的安装命令。它要求上层先完成身份核对与私有目录暂存，核对精确 PID／配置哈希／程序哈希／服务，拒绝环境认证覆盖及未审查的服务扩展；新实例须经面板复核确认，否则恢复目标旧实例。非 systemd 系统不能套用。

直接下载二进制手工安装也必须使用独立程序名和相邻归属标记，配置位于同一目录。不得通过重命名成 `nezha-agent` 或软链接旧目录实现迁移。

## 发布注意

先验收新 Agent 包和配套面板，再按发布流程启用版本入口。旧面板生成的是 `NZ_*` 命令，不能与新脚本混用；更新面板后重新复制安装命令。不要在安装包不存在时推送新的版本指针。发布与线上迁移是独立步骤，须分别验收。

隔离保证限于正常安装／升级／卸载行为，不保证恶意脚本、管理员手动全盘删除、任意第三方脚本不会破坏其他程序。两个 Agent 同时运行会各自采集并消耗资源；若配置同一面板的同一 UUID，连接仍可能互相替换，必须使用各自合法身份。
