# DDnezha 稳定性与安全修复移植

以 DDnezha v0.0.29 为基础，按功能移植官方修复，保留 DDnezha 品牌、版本、安装入口及现有扩展功能。

## 改动

1. 周期流量统计使用独立互斥锁和深拷贝，避免并发更新与读取导致崩溃。
2. IP 尚未知时不执行 DDNS 更新，避免面板重启或 Agent 离线期间误删除 DNS 记录。
3. POST /api/v1/logout 撤销当前浏览器会话；其他设备保持登录。前端等待服务器确认，网络失败可重试，过期会话仍跳转登录页。
4. API 令牌绑定签发时的账号凭据版本；修改密码、账号凭据或验证器设置后旧令牌及其文件传输链接失效，已登记的连接关闭。旧安装令牌一次性原子迁移，重启不会重新激活失效令牌。
5. HTTP/2 限制请求头、帧大小及无进展写入时间；不设置整段响应超时，保持 Agent、终端和下载长连接。
6. 普通计划任务和服务探测输出超过 64 KiB 时按 UTF-8 字符边界截断。备份安装、凭据迁移等专用回复在截断前独立处理。任务通知保留 DDnezha 自定义模板，使用 4 个工作线程和 64 条等待队列；队列满时记日志并跳过该通知，不阻塞 Agent。
7. 引用 ID 去重，去除无效的关闭项，限制 DDNS 域名和告警子规则数量。普通 API 请求体 1 MiB，美化及通用设置保留 2 MiB；备份、SSH、其他专用接口保留更严格的既有限制，文件上传仍使用专用流式接口。

nz-jwt、nzp_、Go 模块路径和权限名称属于兼容性接口，本轮不改名。新增用户文案和文档使用 DDnezha。保留上游版权及来源信息。

## 兼容性复核

- 原有网卡选择、流量周期、主题、备份、SSH 防护及远程管理逻辑保留；Agent 源码与协议没有改动。
- API 文档的名称、说明及支持入口使用 DDnezha；许可证和上游来源信息保留。
- 旧 API 令牌在首次升级时保留有效状态；包括早期 users 表尚无 token_version 列的数据库。迁移后改密会撤销旧令牌，随后重启也不会恢复有效。
- 退出接口沿用现有鉴权错误格式；不会把业务约定的 HTTP 200 / ApiErrorUnauthorized 改成不兼容的响应。
- 从授权状态退出时取消续期；请求失败保留页面并提示重试，过期登录仍进入登录页。
- 超过通知队列容量的消息会记录日志并跳过；这是避免故障通知服务拖住 Agent 的明确边界，不承诺无限队列或关机后重发。

## 验证

验证使用构建机隔离工作目录、独立数据库和回环地址。未在生产物理机、拨号、VM 或业务网络上做实验。

- 后端：全量普通测试、race/shuffle、Vet、Gosec 和编译；Windows、Linux、macOS 矩阵。
- 兼容性：真实 Agent 长连接压力测试；Windows 原生面板启动/停止/重启检查。
- 前端：71 个测试文件，486 项通过、2 项按平台/环境条件跳过；类型检查与生产构建通过。跳过项是本轮 Linux 环境不适用的 Windows 命令执行/导出用例。
- 浏览器：390px 手机及 1440px 电脑；3 小时自动续期、临时网络失败重试、过期回到登录页、退出撤销失败重试等 8 项全部通过。退出重试还分别连续重复 3 次。
- 安装包：嵌入正式前端与真实 GeoIP 数据，验证版本输出、IPv4/IPv6 定位、登录/退出、其他设备会话保留、升级数据库、历史数据、崩溃恢复与分组/服务器 ID 维护。
- 完成第一轮矩阵后复查并补充了早期数据库迁移测试；最终提交继续执行相同 GitHub 检查。可在仓库 Actions 中按分支 test/ddnezha-upstream-hardening-20261121 查询对应提交的结果。

本文件描述隔离验证版本；正式发布、阿里面板部署和服务器 Agent 升级是独立步骤。
