# 服务器分组系统 ID

服务器分组使用实际数据库 ID，按当前 ID 升序保持 1..N 连续编号。删除单个或多个分组后，在同一事务内移动剩余分组和 server_group_servers.server_group_id，并重置自增序列。空列表后新建为 1。服务启动时也会整理旧版本遗留的空缺。

- 不改变服务器系统 ID、UUID 或分组成员归属。
- 不调整通知分组。编号基于全站服务器分组，权限筛选后的子列表不保证从 1 开始。
- 不重写既有服务器操作历史。受影响服务器追加分组编号前后变化记录。
- 发现悬空分组关联时停止整理，不猜测或丢弃关联；事务失败全部回滚。
- 管理端移动端使用横向滚动表格，与电脑端使用相同数据与操作。

## 并发与 API

数值 ID 会被重新使用，编辑和删除前必须读取最新列表：

- GET /api/v1/server-group 每条响应新增 revision。
- PATCH /api/v1/server-group/:id 的表单必须携带该条 revision。
- POST /api/v1/batch-delete/server-group 仍接收 ID 数组，并必须附带 revisions 查询参数，其值为 URL 编码 JSON 对象，例如 {"1":"...","3":"..."}。
- 缺少或过期 revision 会拒绝操作并提示刷新。旧页面/调用程序不能仅凭旧 ID 修改其他分组。
- 新建无需 revision；成员和 API Token 权限检查保持不变。

## 服务器 ID 手动重分配

服务器排序与系统 ID 仍然分开。只有显式调用现有重分配接口，才按提交的完整顺序重新分配服务器 ID。终端会话元数据按 UUID 匹配新 ID，已退役机器的会话不绑定到新机器；既有历史中的 ID 保留为历史快照。重分配期间暂停旧运行态 ID 的流量写入，完成后重启面板。

测试覆盖：首/中/尾删除、批量/全部删除、重新创建、关联完整性、事务回滚、旧请求拒绝、实际二进制启动迁移和重启后持久化，以及手机/电脑明暗主题操作。
