# 手动服务器排序

服务器的默认展示顺序统一在后台「服务器排序」中设置：

1. 电脑按住整行拖动，按住期间可使用鼠标滚轮上下浏览列表，找到位置后松手；放置标记显示插入位置，靠近列表边缘可自动滚动。Esc、离开窗口或在列表外松手取消本次拖动。
2. 手机可拖动左侧手柄；在行其他位置滑动仍正常滚动列表。手机或键盘用户也可点击每行的上移／下移按钮。
3. 点击「保存」后，前台默认顺序和后台列表同步生效。未保存直接关闭会放弃草稿；未移动时保存按钮禁用。
4. 系统 ID、UUID、所属用户、其他设置和监控历史不因普通排序而改变。

批量权重分配、服务器编辑里的权重输入和服务器列表的括号权重均已移除；旧权重接口 `POST /api/v1/server/weights` 不再提供。普通编辑接口忽略旧页面传来的 `display_index`，不会重置手动顺序。

为兼容旧数据与前台主题，数据库／只读响应保留内部 `display_index` 字段，仅由手动排序保存时维护。升级不迁移、不重写现有顺序；默认顺序保持当前展示结果。前台访客临时选择的名称／负载等排序仍是查看方式，切回默认后恢复管理员设定顺序。

红色「重新分配系统 ID」是独立的维护功能，仍需二次确认；普通排序不要点击它。

管理员接口：`POST /api/v1/server/order`，请求 `{"server_ids":[63,47,71]}`，必须包括当前全部服务器且无重复。PAT 需要 `nezha:admin:*` 和所有机器的访问权限。保存使用事务与审计，成功后一次更新运行时列表，不触发 DDNS 或 Agent 操作；列表变化、权限不足、数据库／审计失败会整体拒绝，前端保留草稿以便重试。

## 新节点追加与排序记录（2026-10-11）

新注册节点的显示位置由注册事务读取的当前末尾决定，追加在其后；不再使用固定默认值 0，也不根据新节点分配到的系统 ID 决定位置。用户把末尾节点移到前面后，下一台新节点仍追加到新的末尾。连续注册和手动保存串行，避免旧顺序覆盖新节点。

手动保存将显示顺序整理成连续内部序号，持久化后同步前后台缓存，重启保持一致；全部变化通过同一事务写入服务器操作历史（排序字段前后值、账号、时间）。历史写入失败则排序回滚，不留下“改了但没记录”的状态。显示序号不是系统 ID，服务器身份与监控历史不会重分配。

本次阿里按用户授权单独整理原有顺序并将 clean-foxhound 放最后；其他安装不会在升级时自动重排。


## 按位置移动（2026-10-11）

每行默认显示“位置”按钮，点击后才展开并聚焦输入框；仅聚焦按钮不会进入编辑。按 Esc 或点击其他位置取消输入，不变更顺序。填写 1 至服务器总数之间的整数，按回车或点击“移到”即可调整草稿，再点击“保存”生效。第 14 位移到第 11 位时，原 11、12、13 位依次变为 12、13、14；不是交换两台服务器，也不会修改系统 ID。无效位置不变更顺序。

拖动落点线显示绿色。拖动、上下箭头及位置输入共用普通排序保存接口，事务更新连续内部排序值和操作历史；只有单独点击红色“按当前排序重新分配系统 ID”并确认，才执行系统 ID 重分配。

## 系统 ID 重分配的维护边界（2026-10-13）

日常调整顺序只需“保存”，无需重分配系统 ID。红色按钮会同步迁移服务器关联及保留的历史曲线，耗时随历史量增加；不能把它当成即时修改显示编号。升级面板不会自动执行此操作。

执行前备份完整 data 目录（SQLite、TSDB、配置与密钥），确认无其他改配置操作，并为历史迁移副本、快照和回滚留出足够磁盘／内存。当前按服务器逐台处理并写日志，导入批次不跨存储分区，完成后正常排空写入、关闭历史库并退出，由服务管理器重新启动。

重排按钮本身不自动施加 CPU／内存资源限制，也不包含外部完整备份、逐采样哈希验证和整目录自动回滚。资源较小或历史量大的面板建议安排专门维护，配置适当资源限制并独立核验后恢复服务；中途不要强制关闭或重启整台机器。

历史操作记录中的当时 ID 不改；终端会话元数据按 UUID 匹配新 ID，普通排序始终不改变系统 ID 或 UUID。

## 排序列表搜索

弹窗顶部可按服务器名称或系统 ID 筛选，支持中文、英文（不区分大小写）及部分匹配；清除搜索可恢复完整列表。搜索只改变显示，不修改节点或排序草稿。

筛选结果仍显示全局排序序号。上下箭头每次移动完整列表中的一个位置，“位置”输入也使用完整列表的位置；拖动时按目标服务器在完整列表中的位置插入。保存始终提交所有服务器，包括搜索暂未显示的节点，不会遗漏节点或重新分配系统 ID。重新打开弹窗会清空搜索。
