# SSH 安全

后台服务器列表的盾牌入口打开独立的 SSH 安全页面。仅管理员可管理；限定服务器的管理凭证仍受节点范围约束。当前版本先支持 Linux，默认关闭，不会因升级 Agent 自动修改现有防护。

## 设置与操作

通知可独立关闭，仅保留监测与防护；开启任一登录通知时必须选择有效通知组。

选择服务器后，可以配置 SSH TCP 端口、成功／失败通知、失败检测周期、触发次数和封禁时长。`-1` 表示永久自动封禁；其他时长至少 60 秒。通知包含服务器、账号、来源 IP、时间、认证方式和结果。连续失败按分钟合并提醒。OpenSSH 不记录尝试的明文密码，本功能不收集密码或修改认证流程。

手动黑名单支持 IPv4、IPv6 和 CIDR，每行一个；最多 2000 项。自动封禁只依据已经确认属于所选 SSH 端口的失败事件。手动规则和自动封禁均只作用于所选 TCP 端口，不修改其他端口、路由、网卡配置或 XUI。

白名单最多 100 项，优先于本功能的黑名单和自动封禁。开启“仅白名单”后，仅白名单来源可以访问所选 SSH 端口；空白名单不能启用。回环地址保留本机访问。白名单不能覆盖其他软件独立设置的防火墙规则。

“封禁列表”分别显示自动封禁和手动黑名单，支持按 IP／网段搜索、翻页和每页 10／20／50／100 项。自动列表由 Agent 按需读取，支持最多 10000 条；旧 Agent 只提供已有预览，页面会提示升级。离线、超时或读取失败明确显示错误，不显示成空列表。

自动记录显示封禁开始和到期时间，永久封禁单独标示；旧记录未保存的时间显示“未记录”，不会用升级时间代替。手动黑名单显示添加时间。

封禁 IP 旁可点击“白名单”，同时加入白名单并提交解封；登录记录提供“拉黑”和“白名单”。白名单优先于本功能的网段黑名单；拉黑仍被较大白名单网段覆盖的 IP 时，会提示先调整白名单网段。设置未保存或版本已变更时，先保存／重新读取再操作，避免覆盖其他修改。

自动封禁可点击“解封”；手动条目可点击“移除”。动态解封不会删除仍然匹配的手动 IP／网段黑名单，必要时移除该规则或加入白名单。页面提交成功只表示命令已排队，须等待 Agent 确认和列表刷新；节点离线时明确显示状态。

本次不包含地区或 ASN 拦截，也不下载相关规则或访问外部网段接口。

## 本机执行与数据保存

Agent 通过 Linux nftables netlink 接口设置自己拥有的独立规则表，无需安装 Fail2ban 或 nft 命令行程序。需要内核支持和对应网络管理权限；不满足条件会显示失败，不能视为防护已生效。

规则在未接入流量的临时表中准备，完成后一次性切换；失败保留原表。仅删除已验证属于当前实例的规则，多实例使用相同 SSH 端口时拒绝冲突配置。自动封禁带内核超时，重启按原到期时间恢复，永久封禁不会变成临时封禁。

Agent 读取 auth.log、secure 或系统日志，初次启用从当前位置开始，不补发历史记录。处理日志轮转、截断、部分行和过长行。日志里的来源端口不是 SSH 服务端口；服务端口通过本机 SSH socket 确认，多监听端口无法确认时不猜测、不触发自动封禁。该环境缺少可读取日志或 socket 信息时会限制对应能力。

完整原始日志留在服务器，由系统原有日志保留策略管理。Agent 的私有状态目录为 /var/lib/DDnezha/ssh/<实例标识>/，目录 0700、文件 0600，保存设置、日志游标、失败计数、封禁到期时间、待投递提醒和近期索引。面板查看时由 Agent 读取最近 24 小时内的最新 50 条。

面板仅持久保存设置、待投递通知和必要的去重／投递状态；已完成通知的内容删除，未完成队列最长保留 24 小时，去重元数据最长 48 小时。Agent 待投递队列有数量和时间上限，超限会显示未能投递的数量。断网不关闭本机已生效的防护，恢复连接后继续确认通知和命令。持久化失败时不会假称新设置已经保存。

## 已有 fb5.sh／Fail2ban

不运行 fb5.sh。识别已有 sshd jail 后，页面先带入原端口、失败阈值、检测周期、封禁时长和白名单，可检查调整。启用原生自动封禁接管时：

1. 在本机私有目录备份并校验原 Fail2ban 配置和 SSH 参数。
2. 读取现有 SSH 封禁及剩余时长，保存迁移记录，准备并核验原生规则。
3. 写入本功能拥有的独立 sshd 禁用覆盖文件，仅停止 sshd jail。
4. 保留 XUI、其他 jail、原配置文件及其封禁记录。

任一步骤失败都不得提前停止旧 SSH 防护；迁移短暂暂停检测的状态有持久标记，Agent 重启会先恢复未完成的旧检测。原有白名单在首次接管时保留并展示，后续保存允许明确编辑。迁移完成后，若旧 sshd jail 被重新启用，页面报告冲突。

迁移备份位于上述实例目录的 migration/；禁用覆盖文件为 /etc/fail2ban/jail.d/zzzz-ddnezha-ssh-native.local，带实例归属标记。不要直接覆盖其他实例的文件。回滚接管需按该次备份核实并恢复旧 SSH jail，然后关闭本功能，保留 XUI 与其他 jail；不能通过全局清空防火墙回滚。

## 经单独授权清理旧防护

正常升级和原生 SSH 接管不会删除 XUI 防护。若管理员明确要求清理 fb5 的 SSH 与 XUI 防护，须先备份、核验原生 SSH 接管，再仅停用并移除确认属于 fb5 的 jail、action 和脚本。XUI 程序、业务配置及其他防火墙规则不属于清理范围；存在共享文件或无法确认归属时保留并单独报告。不能执行全局防火墙清空或直接卸载共享 Fail2ban。

## 验证与发布

单元和浏览器测试使用假服务器、假通知组；不向真实通知渠道发送测试消息。内核和 Fail2ban 集成测试只允许在与宿主不同的隔离网络命名空间中执行，并使用独立配置、日志和 socket。覆盖 IPv4／IPv6、TCP 端口隔离、UDP 保留、白名单、仅白名单、动态封禁及到期、手动解封、多实例冲突、失败回退和 XUI 保留。

部署前备份面板程序、配置及一致性数据库备份；升级 Agent 只替换程序，保留 UUID、密钥、网卡选择和业务网络。后台设置默认关闭，升级不自动进行 SSH 防护接管。
