# TG 服务器管理菜单

适用于 custom-2026.10.10.2 及之后版本；已同步阿里、GitHub 源码及 Linux／Windows 安装包。

## 使用

1. 使用仅服务本面板的机器人，在 Telegram 中私聊并点击 Start。保留现有 Bot Token、发送接口和 Chat ID。
2. 后台“通知 → TG 机器人设置”选择对应通知，打开“启用 TG 机器人”。未添加 TG 通知时先显示添加引导，不能直接启用；可通过“添加 TG 通知”打开原通知编辑器。机器人设置采用展开式分区，五个菜单项、登录成功／失败提醒、每日流量推送可分别开关；即将到期范围默认未来 7 天，允许 1–365 天。点击“保存设置”后生效，无需发送测试通知，不改动通知凭据或模板。原通知编辑器不再重复设置机器人功能。
3. 私聊输入框左侧“菜单”直接提供五个并列入口：服务器概览（`/servers`）、在线服务器（`/online`）、离线服务器（`/offline`）、即将到期服务器（`/expiring`）、今日流量统计（`/traffic`）。点击分类即返回相应列表，无需先进入总览。原消息下的分类、翻页与刷新按钮继续保留。首次菜单未刷新时，可关闭后重新展开或重进聊天，也可直接发送对应命令。
关闭单项后，TG 左侧菜单和新回复按钮隐藏对应入口；直接命令及旧消息按钮也会拒绝对应查询。“今日流量统计”关闭时，昨日／固定日期明细同样关闭，但独立开启的每日推送继续发送汇总（不附带查询按钮）。已有安装升级时五项默认保留开启，原提醒配置保持不变；主开关关闭会停用全部机器人查询、登录提醒及日报。

4. 每页 15 台，可翻页、刷新和切换分类。查询更新原消息，避免重复刷屏；每秒最多一次、每分钟最多 20 次。设置中显示连接／暂停状态。

在线判断与面板一致（30 秒内上报）；在线／离线按手动顺序排列。即将到期只包含当前时间之后、范围内的到期项，最近到期优先，不包含已过期或未配置日期的服务器。复用现有计费日期与自动续期逻辑；自动续期推算会标注，并非付款确认。

## 权限与边界

- 仅支持官方 HTTPS Telegram Bot API 和数字私聊 Chat ID。不支持群组、频道或话题。
- 私聊 Chat ID 同时是发送人白名单；其它 TG 用户、群消息、伪造回调上下文不返回服务器信息。
- 查询使用通知所属面板账号的当前权限：管理员可查全部，普通成员仅查自己的服务器。服务器查询展示名称、系统 ID、状态／最后上报时间、到期信息或流量，不展示服务器 IP、备注、密钥和命令；登录安全提醒单独包含登录来源 IP。
- 按钮回调再次校验发送人、聊天、原消息机器人、配置与账号权限。关闭／删除菜单配置后，不再返回列表。旧消息已发送的内容不会远程销毁。
- 原有五项菜单仅查询；默认关闭的“网页终端”是独立的 TG 身份认证入口，只授予服务器终端权限，不签发后台登录会话、不改变正常后台登录及验证器规则。启用终端后，TG 账号或已登录设备遭接管可能导致服务器被操作，应启用 Telegram 两步验证并保护设备。不能承诺绝对安全。
- 开启／变更已开启菜单需本人浏览器管理会话及现有 CSRF 校验，不接受个人访问令牌 PAT。关闭菜单也须浏览器操作。普通告警通知功能不变。

## 运维

每个 Bot Token 仅允许一份启用配置，使用长轮询，无需公开 Webhook 或新端口。发现已有 Webhook 不删除；接收冲突或授权失效会暂停，修正后关闭再开启。网络故障限速重试。菜单注册只修改绑定私聊的命令作用域，不写全局／群菜单。停用时尽力清除私聊菜单；网络异常导致旧菜单仍显示时，后台仍拒绝继续查询。

数据库新增 notifications.telegram_menu、telegram_menu_cursors 及 telegram_daily_deliveries（日报日期和发送状态，不含消息或凭据）。后者只存 Bot Token SHA-256 指纹与更新游标，不重复保存 Token。游标在回复前持久化，防止重启重复处理；因此中断时可能漏掉单次回复，重新点击即可。日志和状态不回显 Token，TLS 始终校验，不跟随跳转。

部署备份须继续保留数据库、配置、TOTP 密钥与终端命令密钥，不能覆盖服务器、排序、历史和账号设置。已有安装默认不开启；本次阿里按用户确认只为原有 TG 私聊通知启用。

## 登录提醒与流量日报

在同一菜单设置中独立开启“登录成功提醒”“登录失败提醒”“每日流量推送”；关闭主开关时一并停用。默认都关闭，本次阿里仅为原 TG 私聊通知按用户要求启用。

登录提醒包含输入账号（限长并过滤控制字符）、时间、方式、来源 IP 和固定原因，如账号不存在、密码错误、验证码错误／过期／已使用、验证码限流或 OAuth 验证失败。默认不发送密码。可在登录失败提醒下独立开启“失败提醒附带密码”：仅本通知所属账号和未识别账号的密码登录失败，附带该次提交的明文密码；其他已识别账号的密码不发送。验证码／恢复码校验失败时，此次密码请求中的密码可能仍正确，开启后也会留在 TG 聊天记录，请谨慎保管。成功登录、GitHub／OAuth2 不附带密码。**验证码、恢复码、Cookie、会话令牌及请求原文不采集进通知；密码仅进入有界内存通知队列，不写面板数据库／日志，JSON／调试输出脱敏。** 输入超过 256 字符明确截断，换行及控制字符转义，避免伪造消息字段。通知不再追加底部的凭据说明；已识别管理员账号显示“管理员”，不修改实际登录账号。公共登录错误仍统一，不向未登录访客暴露账号存在性。管理员通知可接收全站登录事件；普通成员只收到能够确定归属自己的账号事件，未知账号仅通知管理员。正常进入第二步验证不作为失败，JWT 签发后才报告成功；绑定 OAuth、刷新会话不报告为新登录。被入口 WAF 直接拦截的请求不会再次进入登录提醒。

提醒通过有界异步队列发送，不阻塞或改变验证结果。全站每分钟最多 10 条失败、20 条成功提醒；超额／队列繁忙的次数附在下一条同类提醒中。队列仅在内存保留，网络失败或重启可能丢失单条提醒，不是完整审计日志，也不影响原有告警。

今日页面分别显示“今日总用量（00:00 至当前）”和“服务器累计总量（最新上报）”，两者均汇总全部有权限的节点，不随明细分页改变。累计总量来自各机最新 Agent 计数器，离线使用最后上报；重启／计数器重置可能改变，不能当作永久历史总账。

今日流量从北京时间 00:00 开始，使用独立日流量账本，不把 Agent 开机累计当作当天流量、不依赖限额配置；上传为出站、下载为入站，双向合计仅用于展示，不改变单向套餐计费。包含当前有权限的离线、无限流量和未设配额服务器。离线缺报、首次启用后的缺失、重启／跨天估算会提示；迟到上报可修正结果，不承诺与运营商账单完全一致。

日报从启用后的下一个北京时间零点开始触发，通常在十余秒内发送一条昨日汇总及双向用量前 10 台；按钮可按固定报告日期查询全部明细，15 台一页。停机后恢复仅补最近一天，不连发全部旧日。保存发送状态防止普通重启重复：Telegram 明确限流时延后重试（最多 5 次），超时、结果不明或发送中崩溃时不盲目重发，以免重复；具体状态存于 telegram_daily_deliveries，失败写入不含凭据的运维日志。此时可以通过菜单手动查询。

### 2026-10-10 流量账本修复

Uptime 的刷新延迟不再触发累计值重复入账；每个方向仅在自己的流量计数器下降时视为重置，不能仅凭运行时间推断未观察到的重启流量。跨天、缺报及计数器重置仍标注估算。

离线维护脚本 `script/repair-plan-traffic-20261010.py` 默认只做 dry-run，部署前必须停止面板并备份完整 SQLite。修复仅针对独立账本启用后的日期：有原始小时记录的按现存记录重算并标注不完整／估算；缺失的保留原字节值、标记为不可核实且排除在展示总量之外。启用前迁移的历史保持不变。原始 transfers、检查点、服务器身份和配置不修改。输出原账本压缩备份与逐条变更清单，并校验事务原子性及回滚；禁止重复应用。小时记录不是运营商账单，无法凭空补齐已经清理的历史。

## 网页终端（阿里试用）

在“TG 机器人设置 → 网页终端”打开独立开关，确认网站 HTTPS 地址并保存。旧安装默认关闭，不自动扩大查询权限。

TG 左侧菜单新增并列的“网页终端”（`/terminal`）。点击“选择服务器”在 Telegram 内打开选择页，支持名称、数字 ID 的部分匹配、大小写不敏感、多个空格分隔关键词和只看在线。明确选择一台后才建立连接；离线节点显示但不能连接。进入后默认打开快捷命令，复用后台手机／电脑终端组件、按键栏、tmux 会话／窗口管理、文件管理与统一确认框。可断开并换服务器；手机不支持全屏时显示横屏提示。

这是复用哪吒 Agent 的交互终端，不是开放 SSH 端口；仍要求 Agent 在线且允许终端执行。权限以 Agent 进程权限为准。文件管理使用同一 Agent 通道，可浏览目录、上传和下载，上传会经过面板转发到节点，不是浏览器直连节点。TG 授权不提供后台管理登录权限。

- 仅接受服务器端验证通过的 Telegram `initData` HMAC；数字用户 ID 必须与绑定私聊接收者一致。不能用用户名、`initDataUnsafe` 或自报 ID 授权。
- 入口 5 分钟有效且只兑换一次；还需 2 分钟内的 Telegram 签名身份。转发链接不足以授权。普通外部浏览器不放行。
- 选择页授权保存在页面内存中，15 分钟到期；连接票据 30 秒内一次性使用，绑定一台服务器及其内部身份。不开 Cookie、不存 localStorage、不签发 JWT/PAT；连接凭据不放 URL。
- 新版共享界面的终端与文件 WebSocket 使用独立一次性票据，绑定当前 TG 授权、节点内部身份和通道类型；不能用面板会话 ID 或其它 TG 授权接管。所有操作经明确的接口白名单，不允许访问任意后台 API。15 分钟授权到期会关闭连接；关闭开关、更换通知绑定、账号权限／会话版本变化、删除或替换节点后，活跃连接约 1–3 秒内撤销。旧版简单终端接口仍保留原有 30 分钟总时限／5 分钟无输入限制。
- TG 不开放“面板保持”；需要离开网页后继续运行的任务请放在 tmux 中。退出只断开 tmux，结束窗口仅终止指定窗口，结束会话关闭全部窗口。仅一个窗口时显示“添加窗口”，多个时每个窗口显示“结束窗口”并另有“新增窗口”。后台记录窗口名称和创建／结束事件。服务器重启不会自动恢复任务。
- 不改原后台登录、验证器、夜间额外密码规则。复用界面但授权独立，TG 请求不携带面板 Cookie，不刷新面板登录。HTTPS 反向代理须支持该路径的 WebSocket 升级。
- 服务日志仅记终端打开/关闭的账号、通知和服务器编号，不记录终端命令、输出或临时凭据。服务重启清空所有临时授权。

部署前应验证签名篡改、其他用户、超时、并发兑换、重复票据、跨站、跨账号节点、禁用撤销及 Agent 连接失败；无 Telegram 真机实测时不能把模拟验证宣称为用户手机已验收。
