# Windows 原生部署

本分支提供 `dashboard-windows-amd64.zip`。它是 Windows x64 面板服务端，不是 Agent。请使用支持 Windows ACL 的本地 NTFS 数据目录，固定运行账号；不要把数据和密钥放在 FAT/exFAT、公开共享目录或不支持 ACL 的挂载中。

## 启动与数据

解压后在 PowerShell 进入安装目录，执行：

```powershell
New-Item -ItemType Directory -Path data -Force
.\dashboard-windows-amd64.exe -c .\data\config.yaml -db .\data\sqlite.db
```

首次启动会生成配置和初始化账号。先在本机完成初始化并修改默认密码，再开放网络访问；监听地址、端口和防火墙由管理员按需配置。不要以默认密码暴露公网。

备份整个 data 目录，包括 config.yaml、sqlite.db、terminal-commands.key 和 TSDB 文件。快捷命令密钥与数据库配套，不能只复制数据库或删除密钥来解决启动错误。旧密钥会在读取前收紧 ACL，密钥内容及已有加密命令不变。

密钥允许当前运行账号、SYSTEM、Administrators 访问，关闭父目录权限继承。其他所有者、符号链接、重解析点、硬链接和不支持安全 ACL 的位置会拒绝加载。切换运行账号前，应由管理员离线迁移文件所有权和权限，不能依赖自动接管其他用户的密钥。

## 停止、重启与异常退出

控制台运行时按 Ctrl+C 或 Ctrl+Break，等待程序显示完成停机后再启动。正常流程为：停止接受新上报 → 等待已接受上报与服务队列完成 → 刷新并关闭存储 → 退出。不要用任务管理器强制结束代替正常重启。

断电或进程被强制结束后，可以用相同目录和配置重新启动；数据库会执行恢复。已写入的数据会保留，尚未持久化的数据不能保证保留。实际磁盘损坏仍需要备份恢复。

本程序不是原生 Windows SCM 服务：不要直接用 sc.exe create 注册可执行文件。需要无人值守开机恢复时，可用 Windows 任务计划程序设置“系统启动时”触发、固定运行账号及工作目录、失败后重试；避免设置强制结束运行时限。任务计划程序的“结束”属于强制终止，不等同于上述正常停机。当前不提供已验收的 Windows 服务包装器。

## 验收范围

CI 在 GitHub 托管 Windows 环境运行权限回归和真实面板进程测试，覆盖创建和旧密钥权限迁移、登录、加密命令、正常停机和重启、进程中断后恢复、Agent 协议上报、SQLite 完整性，以及中文/空格路径。发布流程还用正式 go_json 二进制验证内置前端和相同生命周期。

这不等于验证了所有 Windows 版本、所有存储介质、第三方服务包装器或真正断电后的硬件行为。具体系统应先备份并做部署验收。Linux 管理脚本 nezha.sh 不适用于 Windows。
